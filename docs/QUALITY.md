# 品質基準 — 「劣らない」の定義

このプロジェクトのゴールは主観的に書かれている（Elden Ring 等に劣らないクオリティ）。
主観のままでは、いつ終わるのか誰にも分からず、改善が進んだのかも分からない。
そこでゴールを**測定可能な13軸**に翻訳し、機械が判定できるようにした。

判定は `node tools/audit.mjs` が行う。合格するまで開発ループが回り続ける。

---

## 判定条件

```
全13軸が 80 点以上 かつ 総合 88 点以上 かつ 未達項目 0 を、連続2回の監査で維持
```

軸の点数だけでは終了条件として甘い。1軸は複数の測定項目の達成率なので、
9項目落としても 85 点＝「80点以上」で通ってしまう。実際それで
「総合97点 PASS・未達10件」という状態が出た。**通ったのに未達が10件ある**のは
判定が壊れているということなので、未達0件を条件に加えた。

連続2回を要求するのは、たまたま通っただけの状態で止めないため。
`docs/AUDIT.md` に履歴が残り、`docs/BACKLOG.md` に未達項目が優先度順で出力される。

---

## 13軸

各軸は複数の測定項目からなる。項目ごとに「目標値」があり、達成率がその軸の点数になる。
目標値は参照タイトル群が実際に持っている規模・深さから逆算している。

### A. 世界のスケールと密度 (weight 12)

広ければ良いのではない。**歩いている間に何かが起き続けるか**が問題。

| 項目 | 目標 | 根拠 |
|---|---|---|
| 踏破可能面積 | ≥ 6 km² | 携帯端末で「広い」と感じ、かつ徒歩で往復できる上限 |
| 地域数 | ≥ 7 | 各地域が固有の敵・色・高度傾向を持つこと |
| バイオーム数 | ≥ 8 | 移動中に景色が変わり続けること |
| POI 密度 | ≥ 20 / km² | 数分歩けば必ず何かに当たる密度 |
| 街道の総延長 | ≥ 6 km | 道が navigation の手がかりになること |
| 構造物の種類 | ≥ 14 | 拠点が使い回しに見えないこと |

### G. 表現力 (weight 12)

見た目を主観で語らないため、**フレームの統計値**で判定する。
昼・夕・夜・嵐・焦土・雪嶺の6状況でサンプルし、全てが帯域に収まること。

| 項目 | 目標帯 | 意味 |
|---|---|---|
| 平均輝度 | 0.10 – 0.58 | 白飛び・黒潰れしていない |
| コントラスト | ≥ 0.11 | のっぺりしていない |
| 彩度 | 0.06 – 0.48 | 極彩色でも無彩色でもない |
| クリップ率 | ≤ 5% | ハイライトが飛んでいない |
| 黒潰れ率 | ≤ 18% | 影が塗り潰れていない |
| 地域間のグレード差 | ≥ 0.03 | 場所ごとに色が違う |
| 昼夜差 | ≥ 0.12 | 時間帯が意味を持つ |

#### 画の解像度

上の帯域は「色が壊れていないか」しか見ていない。**テクスチャのない平坦な
ローポリのフレームでも全部通ってしまう**——実際、一度それで総合100点が出た。
基準として機能していなかったということなので、画に情報が入っているかを
直接測る項目を足した。フラットシェーディングのフレームは、定数色の面が広く、
勾配がほとんどなく、出現する色数が少ない。それをそのまま数える。

| 項目 | 目標 | 意味 |
|---|---|---|
| 表面ディテール（Sobel勾配の平均） | ≥ 0.25 | 面に情報がある |
| 平坦領域率（3x3がほぼ定数の画素） | ≤ 10% | 塗り潰された面が支配的でない |
| 局所コントラスト（8x8タイルのRMS） | ≥ 0.060 | 微細な陰影がある |
| 色の多様性（色相/彩度/明度のビン数） | ≥ 120 | 単色に潰れていない |

ノイズを足せば勾配は上がる。それを防ぐため、勾配と**同時に**平坦領域率・
局所コントラスト・色数を見る。一様ノイズは勾配だけ上げて局所コントラストの
構造を作らないので、4つ揃って動くことが「本当に情報が増えた」条件になる。

空は測らない。滑らかな空のグラデーションは**正しい**もので、それを平坦だと
数えると、夜のシーンが「夜空があるせいで」不合格になり、大気にノイズを
入れる方向に報酬が出てしまう。試されるべきは世界の側なので、測るのも
世界の側にした。

除外は**深度で**行う。画面の割合で切る方式は2回試して2回とも失敗している。
1回目は `gl.readPixels` がボトムアップに返すことを見落とし、捨てたかった側を
そのまま残していた。2回目は向きを直したが、それでも駄目だった——カメラは
約11度上を向いているので真の地平線は画面高67%付近にあり、「下62%」の窓の
3〜5割はどう測っても空になる。深度はどの画素が空かを正確に知っている。
地平線のシルエットは実在する構造なので、近傍9画素のいずれかに地物があれば
採用する。

#### しきい値を引き直した経緯（2026-08-04）

上の「画面下 62%」は、**2026-08-04 まで実装されていなかった**。
`gl.readPixels` は行をボトムアップで返すため、`y` を `0.38h` から `h` まで
走査するコードは画面の**上 62%**——つまり除外したかった空そのもの——を
測っていた。ここまでの数値は全て、地面ではなく空と遠景に対するものだった。

修正すると当然どのシーンの値も上がり、旧しきい値（0.12 / 20% / 0.030）は
全シーンが素通りする。間違った領域に対して較正されていたのだから当然で、
そのまま「合格」にするのは判定を捨てるのと同じなので引き直した。

新しいしきい値は**修正後の全6シーンの中央値付近**に置いてある。
つまり「世界で最も弱い場所が、今の世界の平均程度にはなっていること」を
要求する。絶対値を天下り的に決めるより、この方が意味のある要求になる。

|---|---|

| 環境遮蔽 (SSAO) | あり |
| 法線マッピング | あり |
| マテリアル種別 | ≥ 10 |
| 動的影 | あり |

## 参照タイトルとの関係

この基準は「同じものを作る」ためではない。
参照タイトル群に共通して存在し、**欠けると明確に安っぽくなる要素**を列挙したもの。

- 各軸の目標値は「これを下回ると、そのジャンルのゲームとして成立しない」水準に置いている。
- 物量そのものではなく、物量が担っている**役割**を軸にしている。
  録音された声ではなく「話者がそこにいる感覚」、手で置いた事実ではなく
  「記憶に残る場所」、記録された人体ではなく「重さと説得力」。

### 但し書きについて

以前この文書には「達成しても物量では及ばない」と書いてあった。撤回した。

物量として挙げていた4つ——モーションキャプチャ、手作業のレベルデザイン、
ボイス、テクスチャ——のうち、テクスチャは既に反証されている。画像ファイルを
1枚も持たないまま、素材が素材として光を返すようになった。不可能だったのでは
なく、手をつけていなかっただけだった。

残り3つを軸 K・L・M として測定可能にした。**不可能だと結論するなら、
測ったうえで、なぜ到達できないかを数値で示してからにする。**
